# ===== CELL 8 =====
def haversine (lon_1, lon_2, lat_1, lat_2):

    lon_1, lon_2, lat_1, lat_2 = map(np.radians, [lon_1, lon_2, lat_1, lat_2])  #Degrees to Radians


    diff_lon = lon_2 - lon_1
    diff_lat = lat_2 - lat_1


    km = 2 * 6371 * np.arcsin(np.sqrt(np.sin(diff_lat/2.0)**2 +
                                      np.cos(lat_1) * np.cos(lat_2) * np.sin(diff_lon/2.0)**2))

    return km

# THEORY, VIVA Q&A, ALGORITHM AND COMPLEXITY - ASSIGNMENT 1 (Uber Fare Prediction, Linear Regression)
#
# 1. WHAT THIS PRACTICAL DOES
# Goal: predict the Uber fare (fare_amount) from the trip distance.
# Steps in the code:
#  a) Load uber.csv and drop the useless columns 'Unnamed: 0' and 'key'. Drop rows with missing values (dropna).
#  b) Compute the trip distance from pickup/dropoff latitude and longitude using the Haversine formula.
#  c) Remove outliers: distance > 60 km, distance = 0, fare <= 0, fare > 100 with distance < 1, fare < 100 with distance > 100.
#  d) Feature engineering from pickup_datetime: Year, Month, Day, Day of Week, Hour.
#  e) Exploratory analysis: trips per year / month / weekday, hour-vs-weekday heat map, mean/median/std, correlation matrix.
#  f) X = Distance (independent), y = fare_amount (dependent). Standardise both with StandardScaler.
#  g) Train/test split 80/20, fit LinearRegression, print R2 score, MAE, MSE, RMSE, intercept, coefficient. Plot the fitted line.
#
# 2. KEY CONCEPTS
# - Linear regression: models y = b0 + b1*x + error. b0 = intercept, b1 = slope (coefficient). Fitted by Ordinary Least Squares (OLS), which minimises the sum of squared residuals.
# - Haversine formula: great-circle distance between two points on a sphere:
#     a = sin^2(dlat/2) + cos(lat1)*cos(lat2)*sin^2(dlon/2)
#     distance = 2 * R * arcsin(sqrt(a)),  R = 6371 km (Earth radius).
#   Needed because latitude/longitude are angles, not straight-line coordinates. The code first converts degrees to radians.
# - Outliers: GPS errors give fares like negative values or 0 distance with a huge fare. They pull the regression line, so they are removed.
# - StandardScaler: z = (x - mean) / std, so the data has mean 0 and std 1.
# - R2 score: fraction of variance in y explained by the model. 1 = perfect, 0 = no better than predicting the mean.
# - MAE = mean(|y - y_hat|). MSE = mean((y - y_hat)^2). RMSE = sqrt(MSE), in the same units as y.
#
# 3. ALGORITHM (step by step)
#  1. Read the CSV; drop identifier columns; drop rows with NaN.
#  2. For every row compute Distance with the Haversine formula.
#  3. Filter out invalid / impossible rows (see 1c).
#  4. Extract Year, Month, Day, Day of Week, Hour from pickup_datetime.
#  5. Set X = Distance, y = fare_amount; standardise both.
#  6. Split into 80% train and 20% test (random_state = 0 for repeatability).
#  7. Fit OLS: find the slope and intercept that minimise sum((y_i - (b0 + b1*x_i))^2).
#     For simple regression: b1 = sum((x - x_mean)(y - y_mean)) / sum((x - x_mean)^2), b0 = y_mean - b1 * x_mean.
#  8. Predict on the test set: y_hat = b0 + b1 * x.
#  9. Evaluate with R2, MAE, MSE, RMSE.
#
# 4. TIME AND SPACE COMPLEXITY  (n = number of rows, d = number of features; here d = 1)
# - Haversine distance for all rows: time O(n), space O(n).
# - Outlier filtering, date feature extraction, group-by statistics: time O(n).
# - StandardScaler: time O(n*d), space O(n*d).
# - Linear regression training (OLS): time O(n*d^2 + d^3) (the d^3 term comes from solving the normal equations), space O(n*d). For d = 1 this is effectively O(n).
# - Prediction: O(d) per sample, so O(m*d) for m test samples.
# - Closed-form OLS needs no iterations. Gradient-descent regression instead costs O(iterations * n * d).
#
# 5. LIKELY VIVA QUESTIONS AND ANSWERS
# Q1. What is regression and why linear regression here?
# A. Regression predicts a continuous value. Fare changes roughly in proportion to distance, so a straight line is a reasonable first model.
# Q2. Why did you use the Haversine formula and not Euclidean distance?
# A. Latitude/longitude are angles on a sphere. Euclidean distance on degrees is wrong, and the error grows with distance. Haversine gives the real surface distance in km.
# Q3. Which variable is dependent and which is independent?
# A. Distance is independent (X); fare_amount is dependent (y).
# Q4. Why remove outliers?
# A. Linear regression minimises squared error, so a few extreme points (negative fares, 0 km trips with big fares) pull the line away from the real trend and lower the score.
# Q5. Why scale the data? Is it required for linear regression?
# A. Not strictly required for plain OLS (the predictions are the same). It matters for gradient-based and distance-based algorithms and keeps the coefficients comparable. Here it is a good-practice step.
# Q6. What does the R2 score tell you?
# A. The share of the fare variation explained by distance. Closer to 1 is better. A low R2 means other factors (time of day, traffic, tolls, passengers) also matter.
# Q7. Difference between MAE, MSE and RMSE?
# A. MAE averages absolute errors. MSE averages squared errors, so it punishes big errors more. RMSE is the square root of MSE and is in the same units as the target.
# Q8. What are the intercept and the coefficient?
# A. The intercept is the predicted value when X = 0. The coefficient (slope) is the change in fare for one unit change in distance. Because both were standardised, the values are in standard-deviation units.
# Q9. What are the assumptions of linear regression?
# A. Linear relationship, independent errors, constant error variance (homoscedasticity), normally distributed errors, and no strong multicollinearity (for several features).
# Q10. What does the correlation matrix show?
# A. The linear relationship between each pair of numeric columns, from -1 to +1. Fare and Distance should be strongly positive.
# Q11. How can the model be improved?
# A. Add features (hour, day of week, passenger count, pickup zone), try polynomial regression or tree-based models, and handle outliers more carefully.
# Q12. What is overfitting? How do you check it?
# A. The model fits the training data too well and fails on new data. Compare the train score with the test score; a large gap means overfitting.
# Q13. Why split into training and testing sets?
# A. To measure performance on data the model has never seen.
# Q14. Why a heat map of weekday vs hour?
# A. It shows the busiest times of the week at a glance, so it supports the exploratory analysis.
