# THEORY, VIVA Q&A, ALGORITHM AND COMPLEXITY - ASSIGNMENT 4 (Diabetes Prediction using KNN)
#
# 1. WHAT THIS PRACTICAL DOES
# Goal: predict whether a patient has diabetes (Outcome = 1) or not (Outcome = 0) with K-Nearest Neighbours.
# Dataset: diabetes.csv (PIMA Indians dataset), 768 patients, 8 input features: Pregnancies, Glucose, BloodPressure, SkinThickness, Insulin, BMI, DiabetesPedigreeFunction, Age.
# Steps in the code:
#  a) Load the data, view info(), describe(), shape, data types.
#  b) In Glucose, BloodPressure, SkinThickness, Insulin and BMI a value of 0 is impossible, so it means "missing". Replace 0 with NaN in a copy of the data.
#  c) Fill the missing values: mean for Glucose and BloodPressure, median for SkinThickness, Insulin and BMI (median is used for skewed columns).
#  d) Visualise: histograms before and after imputation, count plot of data types, missing-value bar plot, outcome balance, scatter matrix, pair plot, correlation heat maps.
#  e) Standardise the features with StandardScaler.
#  f) Split: 2/3 train, 1/3 test, stratified on the outcome, random_state = 42.
#  g) Train KNN for k = 1 to 14 and record the train and test accuracy; plot both. Print the best k.
#  h) Choose k = 11, fit the final model, print its score, plot decision regions and the confusion matrix.
#
# 2. KEY CONCEPTS
# - KNN: classifies a sample by the majority class of its k nearest training samples (Euclidean distance). It is non-parametric and lazy (no training step, it just stores the data).
# - Imputation: replacing missing values with an estimate. Mean for roughly symmetric data, median for skewed data (the median is robust to outliers).
# - Stratified split: keeps the same proportion of diabetic / non-diabetic patients in train and test sets.
# - Choosing k: small k = low bias, high variance (overfits; train accuracy at k = 1 is 100%). Large k = high bias, low variance (underfits).
# - Euclidean distance: d(a, b) = sqrt( sum_i (a_i - b_i)^2 ).
# - Confusion matrix [[TN, FP], [FN, TP]]: for diabetes, a false negative (a sick patient labelled healthy) is the most dangerous error, so recall matters.
# - Correlation heat map: shows which features move with the Outcome (Glucose is usually the strongest).
#
# 3. ALGORITHM (KNN)
#  1. Clean the data (replace impossible zeros with NaN, impute).
#  2. Standardise every feature to mean 0 and std 1 (distances must be comparable).
#  3. Split into train and test sets.
#  4. For each k in 1..14: fit KNN, compute train and test accuracy.
#  5. Choose the k with the best test accuracy (here k = 11 was used).
#  6. To classify a new patient x:
#      a) compute the distance from x to every training patient,
#      b) sort and take the k nearest,
#      c) predict the most common Outcome among those k.
#  7. Evaluate with accuracy and the confusion matrix.
#
# 4. TIME AND SPACE COMPLEXITY  (n = training samples, d = 8 features, m = test samples)
# - Imputation and scaling: O(n*d).
# - KNN training: O(1) time (it only stores the data); space O(n*d).
# - Prediction for one sample: O(n*d) with brute force, plus O(n log n) if you fully sort the distances (or O(n log k) using a heap). A kd-tree can reduce this to about O(log n) when d is small, as here.
# - Testing m samples: O(m*n*d).
# - The loop over k = 1..14 fits 14 models and scores each on train and test sets, so the cost is about 14 * (n + m) * n * d. Here n = 512 and m = 256, so it runs instantly.
# - Pair plot and scatter matrix cost O(d^2 * n) to draw.
#
# 5. LIKELY VIVA QUESTIONS AND ANSWERS
# Q1. Why is KNN called a lazy learner?
# A. It does no training; it stores all data and does all the work at prediction time.
# Q2. Why replace the zeros with NaN?
# A. Zero glucose, blood pressure or BMI is medically impossible, so these zeros are really missing values. Leaving them as 0 would distort the distances and the statistics.
# Q3. Why mean for some columns and median for others?
# A. The histograms show that Glucose and BloodPressure are close to symmetric, so the mean is fine. SkinThickness, Insulin and BMI are skewed with outliers, so the median is a safer estimate.
# Q4. Why is scaling very important for KNN?
# A. KNN is distance based. Insulin ranges up to about 800 while DiabetesPedigreeFunction is below 3, so without scaling Insulin would dominate every distance.
# Q5. Why stratify the split?
# A. The classes are imbalanced (about 65% non-diabetic, 35% diabetic). Stratifying keeps the same ratio in both sets, so the evaluation is fair.
# Q6. How did you pick k? What happens at k = 1?
# A. By trying k = 1..14 and comparing the test accuracy. At k = 1 the train accuracy is 100% because each point is its own nearest neighbour, but the test accuracy is poor (overfitting).
# Q7. What is the bias-variance trade-off in KNN?
# A. Small k: low bias, high variance. Large k: high bias, low variance. The best k balances them.
# Q8. Why is odd k preferred?
# A. It avoids tied votes in binary classification.
# Q9. Which distance metrics can KNN use?
# A. Euclidean, Manhattan, Minkowski, Hamming (categorical data), cosine.
# Q10. What does the confusion matrix tell you here?
# A. TN = healthy predicted healthy, TP = diabetic predicted diabetic, FP = healthy flagged as diabetic, FN = diabetic missed. In medicine, reducing FN matters most.
# Q11. What are the advantages and disadvantages of KNN?
# A. Advantages: simple, no training, works for multi-class, naturally non-linear. Disadvantages: slow prediction on large data, high memory use, sensitive to scaling and irrelevant features, suffers in high dimensions.
# Q12. What does the correlation heat map show?
# A. The linear relationship between each pair of features and with Outcome. Features strongly related to Outcome (Glucose, BMI, Age) are the most useful.
# Q13. What does the decision-region plot show?
# A. How KNN divides the feature space into regions for class 0 and class 1. Only two features can be drawn, so the other features are held at fixed filler values.
# Q14. How could this practical be improved?
# A. Fit the imputer and scaler on the training data only (inside a Pipeline) to avoid data leakage, use cross-validation to choose k, try distance weighting (weights = "distance"), and report precision, recall and F1.
# Q15. Is there any data leakage in the code?
# A. Yes, a small one: the scaler and the imputation are applied to the whole dataset before splitting, so test-set statistics influence the training features. This is acceptable for a classroom exercise but should be mentioned.
